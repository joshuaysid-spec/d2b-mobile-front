# 연관 진행 목록 (AnlPrgrsList) — 진행현황 시트 세부단계 클릭 동선

> 작성: 2026-07-10. **모바일 화면설계서에 없는 화면** — PC 버전 설계 동선을 준용해 기획자 지시로 추가.
> 화면ID 미채번 상태(임시 ID `anlPrgrsList`, '연관' Anl 접두 관례). **기획에서 화면ID 채번 시 폴더/파일명 교체 필요.**

## 배경

상세 화면(조달계획/입찰공고/입찰진행/개찰 등)의 가로 스텝바 우측 ▾ 를 누르면 "진행현황" 바텀시트가 열리고,
생애주기 1·2depth(조달계획 > 조달계획/사전규격, 입찰 > 입찰공고/입찰진행/개찰, …)가 표시된다.

여기서 **세부단계(2depth)를 클릭하면 각 상세 페이지로 직행하는 게 아니라, 해당 단계에서 "현재 건과 엮인
(통합참조번호 등 동일 계열) 연관 건들"만 모아 보여주는 목록**으로 이동한다.

- 연관 건은 **대체로 단건**, 더러 2건(예: 정정/재공고).
- 모바일에선 상세→상세 직행이 일반적이지만, **PC 버전이 목록 경유로 설계**되어 있고 복수 건 케이스가 있어
  기획 확정으로 **페이지(목록) 방식**을 채택했다.

## 확정안 — 페이지 구성 (현행 구현)

- **페이지**: `src/ui/biz/cm/anlPrgrsList/AnlPrgrsListPage.tsx` · 라우트 `/anl-prgrs` (헤더 타이틀 "연관 목록")
- **구성(기획 확정)**: 상단 스텝바(가로 StepBar — **기존 상세와 동일한 대단계 5칩**(조달/입찰/계약/이행/대금청구).
  260710: 세부단계 8칩 안은 상세와 달라 혼동 유발로 폐기) + **총건수**(SectionTitle info `총 N건`,
  좌측에 **현재 세부단계명** — 어떤 단계의 건수인지 여기서 표시) + **카드 UI 리스트**(CardList)
- **스텝바 표시 규칙(260710 확정)**: **doing(빨강) = 지금 보고 있는 단계 · done(체크) = 기준 건이 진행한
  단계(`prgrsStg` 이하) · todo = 미진행**. `prgrsStg` 는 진입한 상세가 state 로 전달(`{ substep, prgrsStg }`).
  예) 계약까지 진행된 건에서 입찰 쪽 연관 목록 보기 → 조달✓ **입찰(빨강)** 계약✓ 이행/대금청구 todo.

- **시트에서 세부단계 클릭 = 즉시 이동** — 확인 버튼 없이 클릭 즉시 시트가 닫히고 목록 전환
  (`StepBar` 가 onClick 항목 클릭 시 시트 자동 닫음 — 상세 화면들의 연관 목록 이동도 동일).

  시트에서 onClick 을 부여하지 않는다(상세용 `buildProgressSheet`·연관 목록용 `buildAnlProgressSheet` 공통).

  `navigate('/anl-prgrs', { state: { substep, prgrsStg } })` (콜백 2번째 인자로 currentStage 를 돌려받아

- **카드 클릭** → 세부단계별 기존 상세 재사용: 조달계획 `/op/:id` · 사전규격 `/op/spec/:id` ·

  진입 state 로 기준 건 `rfrncNo` 를 함께 넘길 수 있게 해둠(현재 목업 단계에선 미사용).

### 지원 컴포넌트 변경

- `StepBar` — `StepItem.onClick?: () => void` 추가(vertical 렌더에서 onClick 있으면 행 전체가 버튼).
- `stepPresets` — `buildProgressSheet(currentStage, onSubstepClick?)` 2번째 인자 추가(2depth 에만 onClick 부여,
  콜백은 `(substep, currentStage)` 로 호출).

### 기존 목록 화면을 재사용하지 않는 이유

기존 통합목록들(조달계획/입찰공고/입찰진행/개찰…)은 검색조건 바·상세필터·페이지크기·더보기가 한 몸인
"검색 컨텍스트" 화면이다. 연관 1~2건 표시용으로 진입시키면 ① 사용자가 필터를 지우는 순간 "연관 건만"
컨텍스트가 깨지고 ② 단계별 목록 화면 5~6개 전부에 연관 모드 분기를 심어야 하며 ③ 목업 검색/페이징 블록
(API 연동 시 통째 교체 예정)에 이중 경로가 생긴다. → **범용 연관 목록 페이지 1개**로 분리.

## 대안 (미채택 — 향후 전환 가능): 페이지 없이 바텀시트에서 해결

연관 건이 대체로 단건이므로, 다음 방식으로 **페이지 이동 없이** 처리할 수도 있다:

- **단건** → 세부단계 클릭 시 해당 상세로 **직행** (모바일 관례: 상세↔상세)
- **2건 이상** → 이미 열려 있는 진행현황 바텀시트 안에서 해당 단계 아래에 연관 건 카드 1~2개를 펼쳐
  보여주고, 선택 시 상세 직행

장점: 신규 라우트/페이지 불필요, BottomSheet 슬롯 조합 컨벤션 그대로, 뒤로가기가 원래 상세로 자연 복귀.
단점: PC 설계(목록 경유)와 동선이 달라짐 — **PC 와 동선 통일이 기획 요구라 현재는 미채택.**
추후 모바일 UX 개선 판단 시 이 방식으로 전환 검토(진입 배선이 `buildProgressSheet` 콜백 한 곳이라 전환 비용 낮음).
